# 触控行为验收清单

模块：`android-app/core-input`（com.android.library，但源码无任何 android.* import，纯 Kotlin 事件模型，JVM 单测）
日期：2026-11-07

## 一、阈值总表

| 阈值 | 默认值 | 定义位置 | 说明 |
|---|---|---|---|
| 点按/拖动位移分界 | 24px | `LookGesture.TAP_SLOP_PX` | 与 Android ViewConfiguration 触摸斜率一致（3x 密度下 8dp）；>30px 会把轻微视角调整误判为点按，<16px 会因手抖误触发视角 |
| 点按最长时长 | 200ms | `LookGesture.TAP_MAX_MS` | 时长 ≥ 200ms 且无位移则不是点按 |
| 长按触发时长 | 400ms | `LookGesture.LONG_PRESS_MS` | ≥ 400ms 无位移 → 按住左键（破坏） |
| 视角灵敏度 | 0.5 | `LookGesture.DEFAULT_SENSITIVITY` | 输出 = 位移(px) × 灵敏度 |
| 摇杆死区 | 24px | `DirectionStick.DEAD_ZONE_PX` | 8dp@3x，过滤原地按下抖动 |
| 摇杆默认半径 | 120px | `DirectionStick.DEFAULT_RADIUS_PX` | 调用方按控件实际尺寸传入覆盖 |
| 摇杆滑出松键倍率 | 1.5 倍半径 | `DirectionStick.SLIP_RELEASE_FACTOR` | 距中心 > 180px（默认）即释放全部 WASD 并结束跟踪 |

## 二、验收项

### 1. 摇杆按触点 ID 跟踪（多指互不干扰）

- [ ] 操作步骤：指 A 按住摇杆区并保持；指 B 同时落在视角区拖动；指 C 按跳跃键。
- 预期：A 全程独占摇杆通道（pointerId 绑定，`TouchRouter.onPointerEvent` DOWN 时经 `zoneResolver` 绑定、UP 时解绑）；B 的拖动只产出视角增量；C 只触发跳跃。MOVE 滑出原区域也不换通道。
- 对应类与方法：`TouchRouter.onPointerEvent` / `TouchRouter.activeBindings`；`DirectionStick.onDown/onMove/onUp`（按 `pointerId` 判断）
- 测试：`TouchRouterTest.multiFinger_eachPointerOwnChannel`、`TouchRouterTest.pointer_bindsZoneAtDown_andKeepsItUntilUp`、`DirectionStickTest.secondPointer_notTracked`

### 2. 视角点按 = 左键单击（放置）

- [ ] 操作步骤：视角区轻点，总位移 < 24px 且时长 < 200ms 后抬起。
- 预期：注入 `MouseButton.LEFT` PRESS 后紧跟 RELEASE（一次放置）。
- 对应类与方法：`LookGesture.onUp`（点按分支）
- 测试：`LookGestureTest.tap_shortMove_shortDuration_firesLeftClick`、`LookGestureTest.tap_boundary_exactly23px_199ms_isStillTap`

### 3. 视角长按 = 按住左键（破坏）

- [ ] 操作步骤：视角区按下不动 ≥ 400ms，期间保持，然后抬起。
- 预期：到 400ms 时注入 `LEFT PRESS`；抬起时注入 `LEFT RELEASE`；400ms 之前无任何注入。
- 对应类与方法：`LookGesture.onMove`（长按触发）、`LookGesture.onUp`（释放）
- 测试：`LookGestureTest.longPress_exactly400ms_withNoMove_firesHold`、`LookGestureTest.longPress_notFired_below400ms`

### 4. 视角拖动 = 相对鼠标移动

- [ ] 操作步骤：视角区按下后位移 ≥ 24px 并继续拖动。
- 预期：越过 24px 的瞬间锁定为拖动（之后回到原点也不变回点按）；每段 MOVE 产出 `postCursorPos(dx × 灵敏度, dy × 灵敏度)`；不注入鼠标按键。
- 对应类与方法：`LookGesture.onMove`（拖动分支 + `emitDrag`）
- 测试：`LookGestureTest.move_exactly24px_isDrag_notTap`、`LookGestureTest.move_23px_isNotDrag`、`LookGestureTest.dragLock_onceMoved_returningToOrigin_stillDrag`、`LookGestureTest.drag_outputIsDeltaTimesSensitivity`

### 5. 摇杆滑出自动松键

- [ ] 操作步骤：摇杆按住并推向 W+D，然后滑到距中心 > 1.5 倍半径处（手指不抬起）。
- 预期：W、D 立即 RELEASE，摇杆停止跟踪该 pointer；该 pointer 后续 UP 不再消费。距离恰好等于 1.5 倍半径不算滑出。
- 对应类与方法：`DirectionStick.update` / `DirectionStick.releaseAll`
- 测试：`DirectionStickTest.slipOut_beyond1_5x_releasesAllKeys_andStopsTracking`、`DirectionStickTest.slipOut_boundary_exactly1_5x_keepsTracking`

### 6. 虚拟按键滑出即释放 + 快捷栏 1..9 数字键

- [ ] 操作步骤 A（滑出松键）：按住跳跃键后手指滑出按键矩形区域。
- 预期：立即注入 `SPACE RELEASE`，无需等抬起；抬起不重复注入。
- 对应类与方法：`VirtualButton.onMove` / `VirtualButton.release`；分发由 `GameChannel.onMove` 完成
- 测试：`VirtualButtonTest.slipOut_releasesImmediately_withoutWaitingForUp`、`VirtualButtonTest.gameChannel_routesByTracking`

- [ ] 操作步骤 B（快捷栏）：点击快捷栏第 5 格。
- 预期：注入数字键 5（`Keys.KEY_5`）PRESS+RELEASE；区域按 9 等分换算槽位 1..9。
- 对应类与方法：`HotbarTap.onTap` / `HotbarTap.onUp`
- 测试：`TouchRouterTest.hotbar_tap_mapsToDigitKey`

## 三、模块边界约束

- 无任何 `android.*` import：事件模型为纯数据类 `InputPointerEvent`（pointerId/action/x/y/timestampMs），由 app 层把 `MotionEvent` 转换进来。
- 不依赖 core-runtime：运行时注入通过 `InputSink` 接口（`postKeyEvent` / `postCharEvent` / `postCursorPos` / `postMouseButton`），app 层负责桥接。
- 区域（摇杆区/视角区/按键区矩形）由调用方以 `Region` + `zoneResolver` 注册，core-input 不感知具体布局。

## 四、UI 接线（M3，2026-11-07）

模块：`android-app/core-ui`（Compose 覆盖层）+ `android-app/app`（GameHostActivity 承载）。
每条行为的 UI 落点：core-input 的状态机不动，core-ui 只做「MotionEvent → InputPointerEvent → TouchRouter」的转换与视觉呈现。

| 行为 | UI 落点 | 说明 |
|---|---|---|
| MotionEvent → InputPointerEvent | `InputOverlay` 根 Box 的 `gameGestureLayer`（`Modifier.pointerInput` + `awaitEachGesture`） | 每个触点（`PointerInputChange.id`）逐事件转为 DOWN/MOVE/UP；`pipeline.dispatch` 消费则 `change.consume()`。菜单/编辑模式打开时该层停止分发，防误触 |
| 区域解析（zoneResolver） | `OverlayInputPipeline.rebuild` 中的 `resolve` | 优先级：快捷栏热区（自管，不走 router）→ 虚拟按键矩形 → 摇杆圆形区（1.35×半径）→ 其余 = LOOK。DOWN 时绑定、UP 才解绑（TouchRouter 契约，滑出不换通道） |
| 虚拟摇杆渲染 + 8 向反馈 | `JoystickCanvas` | 底座/滑块/8 向标记 Canvas 绘制；按下时浮动底座=落点（与 DirectionStick 圆心一致），滑块偏移钳制到半径；扇区角量化与 DirectionStick 相同；滑出松键（`stick.isTracking=false`）时视觉复位 |
| 虚拟按键（HOLD/TAP、滑出松键） | `VirtualButtonLayer` + pipeline 内 `VirtualButton`/`GameChannel` | 按下高亮（观测 `isPressed`）；滑出/抬起释放均由 core-input 状态机完成，UI 只显示 |
| 快捷栏热区 1..9 | `HotbarStrip` + pipeline 内 `HotbarTap` | 屏幕底部 1/6 高度整行 9 等分；DOWN 记 pointer、UP 时 `onTap` 注入数字键，选中槽位闪烁反馈 |
| 按键位置/大小/透明度调整 | `ButtonLayoutEditor`（菜单「按键布局编辑」开关进入） | 拖动改 anchor、滑条改 sizeDp/alpha；每次改动结束经 `pipeline.updateLayout` 持久化 |
| 布局/灵敏度持久化 | `SharedPrefsOverlaySettings` | SharedPreferences `tipcl_overlay`：布局 JSON（`layout_json`）+ 灵敏度（`look_sensitivity`）；布局 JSON 同时镜像到 appData `overlay_layout.json` |
| 灵敏度 → LookGesture | 菜单滑条 → `pipeline.updateSensitivity` | LookGesture.sensitivity 为构造期参数，故更新时重建 LookGesture+TouchRouter（进行中触点绑定清空，可接受）并持久化 |
| 菜单面板 | `GameMenuPanel`（右上角 ☰ 打开的左侧抽屉） | 暂停（注入 ESC PRESS+RELEASE）/ 回主菜单（回调宿主 finish）/ 灵敏度滑条 / 布局编辑开关 |
| 切后台防卡键 | `GameHostActivity.onPause` → `pipeline.reset` | 清空全部触点绑定与按键按下状态 |
| 注入桥 | `GameHostActivity.gameInputTarget`（实现 core-ui `GameInputTarget` → core-runtime `InputInjector`） | GLFW_PRESS=1/RELEASE=0；鼠标键 0/1/2 = 左/右/中；cursorDelta 直通 `postCursorPos` |

默认键位（可编辑持久化）：跳跃=Space(32, HOLD)、潜行=左Shift(340, HOLD)、聊天=T(84, TAP)、背包=E(69, TAP)、丢弃=Q(81, TAP)；摇杆=WASD 8 向；快捷栏=1..9；视角区=点按放置/长按破坏/拖动转视角。

验证：`gradle :core-ui:compileDebugKotlin :app:compileDebugKotlin` BUILD SUCCESSFUL；`:app:assembleDebug` 仅在 core-runtime native（tipcl_runtime.c JNI 签名）失败，Kotlin 侧全部通过。

## 五、自动化回归（M5 真机工具包，2026-11-07）

位置：`scripts/device/`（bat + adb，GBK 代码页安全，纯 ASCII 注释）。
前置：`adb` 在 PATH 或 `%LOCALAPPDATA%\Android\Sdk\platform-tools`；设备开启 USB 调试；先跑 `install.bat` 装 APK。

### 脚本与行为的对应

| 验收项 | 自动化脚本动作（adb shell input） | 人工判定标准 |
|---|---|---|
| 1. 摇杆按 pointerId 跟踪 | `touch_regress.bat` 第 1 项：脚本按住摇杆区 3s（`input swipe x y x y 3000`），测试者同时拖视角区、按跳跃 | 摇杆全程独占通道；视角拖动只转视角；跳跃只触发一次；无串扰 |
| 2. 视角点按=左键单击 | 第 2 项：`input tap`（快、短）落在视角区 | 恰好一次放置，之前无视角旋转 |
| 3. 视角长按=按住左键 | 第 3 项：`input swipe x y x y 1200` 同点长按 | ~400ms 后开始破坏持续到抬起；前 400ms 无注入 |
| 4. 视角拖动=相对鼠标移动 | 第 4 项：水平往返两条 swipe（600ms/900ms） | 视角按位移比例旋转，无按键注入 |
| 5. 摇杆滑出自动松键 | 第 5 项：按住摇杆后滑出至 >1.5 倍半径（不抬指由 swipe 模拟） | 越界瞬间 W/D 释放、角色停走；抬起后无重复注入 |
| 6. 虚拟按键滑出+快捷栏 1..9 | 第 6 项：脚本 tap 快捷栏中点（5 格）；滑出松键由测试者手动按住跳跃滑出 | 快捷栏切到 5 格；跳跃滑出立即 RELEASE、不等抬起 |

### 使用流程

1. `install.bat [apk]` —— 探测 adb → 装 `dist\*.apk`（或 CI artifact）→ 启动 `.LauncherActivity`。
2. `run_all.bat [apk]` —— 一键会话：install → `logcat_game.bat 60`（TipCL.* 过滤 + dropbox/am crash 历史到 `logs\`）→ `touch_regress.bat`（逐项 y/n 判定并汇总）→ `perf_sample.bat 60`（gfxinfo/cpuinfo/meminfo 采样到 `logs\perf_*\summary.txt`）→ 生成 `logs\session_*.md` 会话报告。
3. 单跑：`logcat_game.bat [秒]` / `touch_regress.bat [jx jy lx ly hx hy]`（可传像素覆盖默认比例坐标）/ `perf_sample.bat [秒]`。

### 自动化的边界

- `input` 命令无法注入真实多点同时事件，验收项 1、6 的第二触点仍需人工配合；其余项脚本生成的手势与阈值定义一一对应（24px 点按斜率、200ms 点按上限、400ms 长按、1.5 倍半径滑出）。
- 崩溃取证是自动的：`logcat_game.bat` 同时抓 `dumpsys dropbox --print`（data_app_crash/anr）与 `am crash` dump，与实时 logcat 一并归档 `logs\`。
